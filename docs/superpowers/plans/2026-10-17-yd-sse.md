# yd 实施计划：SSE 的兼容性、性能与功能补全

> 需求来源（用户原话）：
> 「SSE中间件也要进行全方位的进行全兼容性、高性能、全功能等方面进行修改和优化。」

## 0. 需求差异说明

只读需求基线未涵盖本节，本文件即差异说明。

## 1. 现状（底子不错，但有三处真问题）

现有 `http/sse` 已实现：WHATWG 线格式（字段顺序 comment→id→event→retry→data）、
`Content-Type: text/event-stream; charset=utf-8`、`Cache-Control: no-cache, no-transform`、
`X-Accel-Buffering: no`、`Last-Event-ID` 解析、心跳、Broker 主题广播、
慢消费者丢帧计数、`WriterSet` 优雅终止、并发写串行化、协程泄漏测试。

逐行审查后的真问题：

| # | 问题 | 影响 |
|---|---|---|
| **C1** | `Connection: keep-alive` **无条件**设置 | HTTP/2 明文禁止连接级头（RFC 9113 §8.2.2），HTTP/3 下更可能直接协议错误；本框架的 server 支持 h2c 与 HTTP/3，这是**实打实的兼容性缺陷** |
| **C2** | `WriteData(s string)` 内部 `[]byte(s)` 转换 | **每次调用一次分配**，而这是最高频的调用形式 |
| **C3** | 无 `Last-Event-ID` 重放 | 客户端断线重连后**丢失断线期间的事件**——SSE 的重连语义因此不完整 |

另有三处功能缺口：事件 `ID` 未按规范校验（含 NUL 或换行时该字段应被忽略）、
`retry` 未校验（非整数应忽略）、单事件无大小上限（可被单条超大事件撑爆内存）。

## 2. 设计

### 2.1 兼容性

- **C1**：`Connection: keep-alive` **仅在 HTTP/1.x 设置**（`r.ProtoMajor == 1`）；
  HTTP/2 与 HTTP/3 不设置该头。同时补测试：h2 请求下响应头**不含** `Connection`。
- **代理缓冲**：保留 `X-Accel-Buffering: no`；文档补充常见反代（nginx / traefik）的额外注意事项。
- **CORS 与凭证**：`EventSource` 的 `withCredentials` 走标准 CORS，
  文档说明需配合 `middleware.CORS` 的 `AllowCredentials`。
- **认证**：`EventSource` **无法设置请求头**，令牌只能经 query 或 cookie 传递——
  文档给出两种做法及其风险（query 中的令牌会进访问日志与 Referer，必须提示）。
- **压缩**：SSE 响应必须不被压缩（现有 `middleware.Compress` 已跳过 `text/event-stream`，保留并加断言）。

### 2.2 性能

- **C2**：新增 `WriteEventString` / 改造 `WriteData` 走**字符串直写**路径，
  在已有 `w.buf` 上 `append(buf, s...)`，**不产生 `[]byte` 转换分配**；基准对比。
- **每连接一个缓冲**（现有设计）保持：帧构造零分配；
  事件缓冲上限由 `Options.BufferSize` 约束，超大事件返回哨兵而不无限增长。
- **心跳**：确认零分配（注释帧是常量拼接），有基准。
- **Broker 扇出**：`QueueSize` 与丢帧策略已在文档中（慢消费者丢帧、发布方不阻塞），
  补基准：N 个订阅者、M 次发布下的 ns/op 与分配。

### 2.3 功能补全

- **`Last-Event-ID` 重放（可选，默认关闭）**：
  `BrokerOptions.ReplaySize int`，每个主题保留最近 N 条带 `ID` 的事件（环形缓冲）；
  重连时若携带 `Last-Event-ID`，先补发其后的事件再进入实时流。
  **边界必须写清**：只覆盖**进程内**、**内存中**的最近 N 条；跨实例或重启后的重放需要外部存储，
  不在本组件职责内——文档明说，避免使用者误以为它是可靠消息队列。
- **`id` 校验**：含 NUL 或换行时**忽略该字段**（按 WHATWG §9.2.6），不写进帧。
- **`retry` 校验**：非十进制整数时忽略该字段。
- **单事件上限**：`Options.MaxEventSize`（默认 1 MiB），超限返回哨兵，不写出半截帧。

## 3. 测试

| 场景 | 期望 |
|---|---|
| HTTP/1.1 建流 | 含 `Connection: keep-alive` |
| **HTTP/2 建流** | **不含** `Connection`，其余头不变 |
| `WriteData` 高频调用 | `allocs/op == 0`（基准） |
| `id` 含 `\n` / `\x00` | 该字段被忽略，其余正常 |
| `retry` 非整数 | 忽略该字段 |
| 超大事件 | 返回哨兵，连接不被写坏 |
| 重放（开启） | 携带 `Last-Event-ID` 重连，先补发其后事件再进实时流 |
| 重放（未开启） | 行为与现在一致（不补发） |
| 重放边界 | 只保留最近 N 条；N=0 等价关闭 |
| 慢消费者 | 丢帧且发布方不阻塞（既有） |
| 优雅退出 | 流被终止、Broker 关闭（既有） |
| 与 `middleware.Compress` | `text/event-stream` 不被压缩 |

## 4. 验收

1. h2 下不发送 `Connection`（有测试）；
2. `WriteData` 基准 allocs/op 为 0；
3. 重放功能默认关闭、行为可预期，且文档明确其**不是可靠队列**；
4. 既有全部 SSE 测试（含优雅退出、并发写、泄漏检测）原样通过；
5. 全仓门禁全绿。

## 5. 已知取舍

- **重放只在内存、只在单进程**：这是 SSE 的固有边界，不试图用内存缓冲伪装成可靠投递。
- **不做事件持久化**：超出组件职责；需要时由使用方在 `Publish` 前自行落库。
- **keep-alive 头不做可配置**：按协议自动判断是唯一正确的做法，给开关只会制造配错空间。
