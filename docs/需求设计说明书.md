
🚀 现代全栈 Web 框架及脚手架（yd）详细需求设计说明书


一、 项目定位与愿景

本框架是由 YunDev团队（yun-dev.cn、yun-dev.net） 倾力打造的极致性能、极低认知负载、高生产力的 Go 语言全栈 Web 框架。项目官方开源仓库托管于 github.com，并严格遵循 Apache-2.0 开源许可协议进行开源与社区共建。
框架通过深度融合 Go 1.27+ + Htmx 4.0 + Tailwind v4，消除传统前后端分离（BFF + SPA）带来的高昂开发成本与复杂性，回归“全栈单体”（Modern Monolith）的高效开发模式。在保持媲美原生 API 框架的并发性能与吞吐量的同时，提供接近单页应用（SPA）的丝滑用户体验。

二、 全局与脚手架（CLI & Governance）


1. 命令行工具（CLI Launcher）

• 功能定义：提供名为 yd 的跨平台命令行工具，负责项目全生命周期的管理与维护。
• 基础配置与基础文件系统集成：
	• 集成 viper 作为全局配置管理中心，支持多格式（TOML/YAML/JSON/YAML v3）动态解析与配置监听。
	• 集成 afero 实现抽象文件系统（Mockable FS），确保脚手架的文件读写、静态资源虚拟化及测试环境下的内存文件系统（MemFS）无缝切换。
	• 集成 pflag 代替标准库 flag，提供完全符合 POSIX 标准的命令行参数解析，赋能脚手架强大的参数交互能力。
• 核心命令规范：
	• yd new <project-name>：一键初始化项目。支持交互式选择可选组件（如数据库驱动、是否启用 gRPC、需要激活的 Htmx 插件等），自动通过 viper 生成初始配置文件，并预置工程元文件（如 .gitignore、.gitattributes、Dockerfile 以及 LICENSE）。
	• yd dev：全生命周期本地开发热重载（Live-Reload）。同时监听 Go 代码、Tailwind 配置文件以及 /web/templates 下 HTML 模板的修改，实现后端自动编译重启与前端无刷新/局部刷新。
	• yd gen <module|crud>：低代码生成器。支持基于数据库 Schema 或 Go Struct，一键生成后端的路由、Controller、Htmx 响应组件以及前端的 Tailwind 页面。
	• yd build：一键跨平台打包。全自动进行静态资源嵌入（go:embed）、Tailwind 样式剪裁压减（Purge/Minify）并产出单一无依赖二进制文件。
	• yd docker：一键 Docker 镜像构建。脚手架通过内置的 afero 文件系统读取预设的高性能多阶段 Dockerfile，自动调用本地 Docker 守护进程，直接将经过 yd build 裁剪压缩后的高并发单体应用打包为超轻量级（约十几MB）的生产环境容器镜像。

2. 多源分层配置引擎与优先级规则（Configuration Infrastructure）

应用启动时，框架通过 viper 构建一个强类型、高鲁棒性的分层配置管理中心，严格遵循以下优先级（由高到低，高优先级完全覆盖低优先级）：
1. 命令行参数（Command-Line Flags）：通过 pflag 显式传入的参数（最高优先级）。
2. 系统环境变量（Environment Variables）：操作系统原生的环境变量，或自动读取项目根目录下的 .env 文件。
3. 本地配置文件（Configuration Files）：基于 yaml/v3 或 TOML 格式的物理配置文件。
4. 框架默认值（Defaults）：代码中通过 viper.SetDefault 定义的安全底线值。
• 多源绑定规范：
	• 环境自动注入：调用 viper.AutomaticEnv()，将环境变量前缀设为 YUNGO_（如 YUNGO_SERVER_PORT）。同时支持下划线自动转换为多级嵌套结构（如 YUNGO_DB_MAXCONN 映射到 db.maxconn）。
	• 命令行无缝覆盖：使用 viper.BindPFlag() 将 pflag 定义的命令行参数直接绑定到对应的配置项（如 --port 或 -p 绑定到 server.port）。当命令行参数触发时，自动越过环境变量和文件项，成为运行时最终生效值。

三、 后端架构要求（Backend Core）


1. 语言基础与异构体系硬件加速

• 版本底线：采用 Golang 1.27.2（及以上版本），充分利用 Go 新版本在泛型优化、垃圾回收（GC）延迟降低、编译器 PGO（Profile-guided optimization）以及标准库结构体增强方面的特性。
• 自适应高性能 JSON 编解码方案：
	• 框架内置统一的 json 包装抽象层，内部通过 Go Build Tags（条件编译） 实现硬件自适应分流。
	• 在 amd64 (x86_64) 架构下，自动绑定 sonic，通过 JIT 运行时编译与 SIMD 指令集释放极致的吞吐性能。
	• 在 非 x86_64 架构下，自动无缝切换为 go-json，确保非 x86 环境下依然维持高性能且 100% 兼容标准库的编解码表现。
• 自适应高性能 Base64 编解码方案：
	• 在 amd64 (x86_64) 架构下，底层自动采用 base64x，利用 SIMD 硬件加速 实现底层数据流的超高性能、零拷贝式 Base64 转换。
	• 在 非 x86_64 架构下，优雅降级采用 Go 原生 encoding/base64 标准库，确保跨平台编译的绝对稳定。

2. 极致性能与高级语法路由模块（Ultra-Performance & Advanced Router）

• 技术对标：超越或对标 HttpRouter 和 Echo 的基数树（Radix Tree）算法。
• 高级部分路径通配与后缀提取（Partial Path & Suffix Matching）：
	• 复杂路由段解析：基数树必须原生支持单路径分段内的混合静态与动态混合匹配（即支持非 / 分隔符的多级动态捕获）。
	• 典型场景支持：/:id.jpg（捕获动态参数 id 且精准匹配以 .jpg 结尾）以及 /:id-xx.png（支持中划线及自定义静态后缀的组合捕获，自动提取 id，剥离静态文本 -xx.png）。

3. 数据层、缓存与高性能分布式队列（Data & Queue Ecosystem）

框架作为高并发应用底座，深度集成以下云原生持久化与异步计算生态插件，所有依赖的配置项一律支持前述的环境变量与命令行层级覆盖：
• ORM 持久化插件（GORM 深度融合）：
	• 采用 gorm 作为标准关系型数据库（MySQL/PostgreSQL/SQLite）的操作核心，提供强大的模型映射与类型安全。
	• 针对高并发场景，默认开启预编译 SQL 缓存（PrepareStmt: true），并结合框架内置的零拷贝日志系统实现慢查询 SQL 的无分配（Zero-Alloc）级别实时打点监控。
• 高性能缓存与高频操作插件（Go-Redis 客户端）：
	• 集成 go-redis/v9 客户端，支持单机、哨兵（Sentinel）及分布式集群（Cluster）部署模式。
	• 提供基于强类型（Generics）的开箱即用缓存装饰器，底层序列化自动绑定硬件自适应的高速 JSON 编译层。
• 企业级分布式异步任务队列（Asynq 插件）：
	• 集成基于 Redis 驱动的高性能异步任务队列 asynq，用于削峰填谷、定时任务及后台长周期事务处理。
	• 提供声明式的 TaskHandler 注册机制，支持动态权重队列划分（如 critical:3, default:2, low:1）、失败重试自动倒退指数算法（Exponential Backoff）以及高内聚的任务上下文追踪。

4. 零拷贝日志系统（Zero-Copy Logging）

• 技术对标：对标并超越 zap 与 zerolog。
• 设计要求：基于类型安全的强类型字段流式写入，利用 sync.Pool 维护字节缓冲区直接写入 io.Writer。

5. 核心中间件与高阶插件体系（Plugin & Middleware Chain）

• JWT 鉴权插件（零拷贝与无缝集成）：采用高性能免反射的 JWT 解析方案，直接利用前述的高速 Base64 与 JSON 自适应底层进行载荷（Payload）提取。
• WebSocket 异步双向通信插件（全行业标准 RFC 闭环）：严格遵循 RFC 6455 行业标准规范，升级和读写底层完全跳过中间缓冲区，直接复用 net.Conn 的 TCP 缓冲区内存。
• SSE（Server-Sent Events）单向实时流插件：提供符合 W3C 标准的文本流响应（text/event-stream），支持后端组件直接以流式（Streaming）HTML 格式向前端定向爆破推送。
• 基础常规中间件：CORS、限流（Rate Limiting）、OpenAPI 3.0、i18n、gRPC 双通道。
• 高级压缩插件：支持 Gzip、Brotli、Zstd 压缩算法与优先级权重自动协商。

6. 现代网络协议与自动化证书（Network & Security）

• 支持 HTTP/1.1、HTTP/2（H2C）以及 基于 UDP 的 HTTP/3 (QUIC) 混合启动。内置自动申请与续签证书管理器（ACME）。

7. 国密合规加密安全工具箱（Guomi Crypto Utils）

为响应高级安全合规与金融级加密需求，框架后端原生内置强类型的国密加密基础套件，严禁外挂高延迟的非 Go 原生组件：
• SM2（非对称加密与数字签名）：提供基于椭圆曲线的公钥加密、私钥解密算法，以及高效的签名与验签接口，用于敏感传输数据（如身份证、银行卡）的端到端加解密。
• SM3（密码杂凑算法）：提供高性能、抗碰撞的哈希摘要工具，全面代替脆弱的 MD5/SHA1，用于系统用户密码的高强度冷存储哈希（加盐散列）。
• SM4（分组对称加密）：支持无线局域网标准的分组密码算法，内置标准的 CBC/GCM 模式，用于本地敏感配置文件、日志隐私字段或数据库关键列的瞬时加解密。

8. 最佳标准项目结构（Standard Layout）与 Docker集成

• 架构规范：严格参考 golang-standards/project-layout 标准规范。
• 默认内置 Docker 编译体系（Dockerfile 模板）：项目创建时在根目录生成经过极致调优的多阶段构建 Dockerfile 文件，底层使用 scratch 镜像。

四、 前端架构与 Htmx 4.0 生態插件深度集成


1. 核心深度集成（Core Infrastructure）

• 前端不依赖 Node.js 繁琐的编译管道（Tailwind v4 编译由 Go 脚手架工具静默处理）。Htmx 4.0 作为事件总线，Tailwind v4 作为样式标准。

2. 前端国密安全沙箱（Frontend Guomi WebCrypto）

为了与后端国密插件形成绝对安全闭环，前端管理端基础模板内无缝集成微型、高性能的纯 JS/Wasm 国密算法库：
• 传输前置置密：表单在通过 Htmx 发送给后端前，若涉及敏感凭证，可声明式触发前端 SM2 异步公钥加密，确保网络传输流（即使在 HTTPS 被旁路监听时）依然具备国密级抗破译强度。
• 密文完整性校验：静态资产和本地缓存凭证支持通过前端 SM3进行完整性校验与摘要比对。

3. Htmx 4.0 声明式基础控件库与生态插件深度集成

• WebSockets / SSE 异步双向通信集成（核心全自动流插件）。
• 多阶段加载与局部骨架屏增强（Preloading & Loading States）。
• Alpine.js / Morphdom 属性完美融合（Idiomorph 精细化 DOM 差量更新）。
• 客户端表单增强与 JSON 序列化插件（JSON & Client-side Validation）。
• 客户端事件响应拦截（Response Targets & Headers）。
• 脚手架针对 Htmx 插件的工程化治理（CLI & Packaging）：由 afero 虚拟文件系统安全地写入并管理，通过 go:embed 统一打包进二进制文件，严禁从外部公网 CDN 动态引入。

4. Tailwind v4 主题与样式统一管理（Styling & Theming）

• 以 Tailwind v4 蓝色系 为默认系统主色调。在全局 CSS 中利用 Tailwind v4 的新特性 @theme 定义语义化 CSS 变量。

5. 开箱即用后端管理平台基础模板（Admin Dashboard Template）

• 左侧常驻/折叠式导航栏、顶部状态栏，中央高吞吐工作区内的所有菜单切换、表单提交一律通过局部无刷新加载，实现 SPA 级别的丝滑用户体验。

6. 前端原生国际化（Frontend i18n Optimization）
